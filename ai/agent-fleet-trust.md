Note:
Back then, it was a team of one. One agent, and me watching every move it makes. It's in manual mode, which means it can't do much of anything without asking me first.
**Presenter cue:** Open an agent in the demo repository, in manual permission mode. Replace <single-issue> with the reserved issue number. Use the agent's permission controls, not a prompt claiming it is in manual mode. Stop at the first permission request.
I tell it to fix an issue, and before it has even read that issue, it stops and asks whether it's allowed to run gh issue view. That's how it goes with a team member I don't trust yet. I approve this, then the next thing, then the one after that. The work gets done, but all of my attention goes into babysitting a single agent, so the team can't grow beyond one. There's nobody left to manage the others.
**Presenter cue:** Pause at the permission request for gh issue view. Approve it and show the next permission request. Permission behavior depends on the installed agent and existing allow rules. Rehearse with an issue read that actually asks for permission; if the first request differs, describe the request on screen rather than insisting it is gh issue view.
Trust changes that. At some point, my skills and the rest of the agent's instructions became reliable enough that I noticed I was saying "yes" to almost everything it asked. Once approving turns into a reflex, it's no longer oversight. It's just me slowing the agent down. So I switch it to auto mode, and it stops asking about every command. It creates a worktree, loads the skill that tells it to reproduce a bug before fixing it, and carries on without me. That's the moment a manager stops supervising and starts delegating.
**Presenter cue:** Switch to your configured auto permission mode and show the agent creating a worktree and reproducing the bug. Use the agent's native controls for the autonomous mode already used in this repository. Let it continue in the background. If the next milestone takes too long, open the prepared equivalent agent session and identify it as earlier work.
The agent opened a pull request, and that kicked off everything I'd expect around a change made by anyone on a team. Workflows built and tested it on Linux, macOS and Windows, and ran the security checks. Review bots, Greptile and Qodo, went through the code over several rounds, and every time they found something, the agent fixed it and pushed again. By the time it comes back to me, all the required checks are green and no review thread is left open. My job comes down to delegating the work and judging the outcome. If something is off, I tell it what to change. That's the other half of trust. Good instructions make the agent reliable, and the pipeline catches whatever still slips through.
